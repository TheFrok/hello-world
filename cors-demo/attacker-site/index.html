ATTACKER SITE — http://localhost:3003

This page simulates a malicious website that exploits CORS misconfigurations in the API server at http://localhost:3001.
Open your browser's DevTools → Network tab to inspect the actual HTTP headers.

VULN 1 — Origin Reflection

Target: GET http://localhost:3001/api/data-reflect

The server reads the Origin request header and mirrors it back as Access-Control-Allow-Origin. Combined with Access-Control-Allow-Credentials: true, any origin — including this malicious one — can read authenticated responses.

VULN 2 — Wildcard + Credentials (Browser Blocks)

Target: GET http://localhost:3001/api/data-wildcard

The server sets Access-Control-Allow-Origin: * together with Access-Control-Allow-Credentials: true. The CORS spec forbids this combination — browsers will block the response. This shows that two wrongs don't accidentally make a right; the server still leaks data to unauthenticated (no-cookie) requests, just not credentialed ones.

VULN 3 — Null Origin (Sandboxed iframe)

Target: GET http://localhost:3001/api/data-null

Some servers whitelist the literal string "null" as an allowed origin. Browsers send Origin: null from sandboxed iframes (sandbox attribute without allow-same-origin). An attacker can host a page that injects a sandboxed iframe, which then makes the cross-origin request and exfiltrates the response via postMessage.

SAFE — Secure Endpoint (Should Be Blocked)

Target: GET http://localhost:3001/api/data-secure

This endpoint only allows http://localhost:3002. When this attacker page (at port 3003) tries to read the response, the browser blocks it because the server returns no CORS headers for unauthorized origins.
